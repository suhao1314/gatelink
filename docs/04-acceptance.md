## 四、待补事项清单

### 必须补（上线前）

| 项 | 说明 | 影响 |
|---|---|---|
| 小程序 AppID 与 AppSecret | 配置后登录才走真实微信身份 | 阻塞 |
| HTTPS 域名 + request 合法域名 | 需已备案域名 | 阻塞 |
| 「扫普通链接二维码打开小程序」规则 | 小程序后台配置 + 上传校验文件 | 阻塞（影响扫码进小程序） |
| 小程序备案 | 备案主体需与小程序主体一致 | 阻塞 |
| 用户隐私保护指引 | 后台填写并配置 | 阻塞 |
| 类目确认 | 以官方最新类目表为准，避免被驳回 | 阻塞 |
| 真机视觉与交互验收 | 开发者工具打开逐页确认 | 阻塞 |
| 审核素材 | 提审时落地页使用自有合规内容 | 阻塞 |

### 建议补（第一批迭代）

| 项 | 说明 |
|---|---|
| 图片压缩 | 商家上传的截图未压缩，建议服务端转 WebP 并限制长边 |
| 内容安全检测 | 接入微信内容安全 API，替代人工审核 |
| 二维码中心嵌 Logo | 需引入图像合成库（如 sharp） |
| 孤儿文件清理 | 异常路径可能残留图片，需定时清理脚本 |
| SQLite 备份 | 定时备份数据库文件到对象存储 |
| `node:sqlite` 生产评估 | 实验性 API，量大后评估迁移 MySQL |
| 数据保留策略 | 原始访问日志建议保留 90 天后聚合清理 |
| 落地页预加载 | 可在首页预拉取最近一个活码的配置 |

### 首版明确不做

套餐计费、代理分销、团队子账号、私有化部署、多级分销、H5 自定义域名池。

理由：先验证有没有人真的用，再谈商业化。

## 五、结论

**可以进入提审流程，但必须先完成第四节「必须补」的全部人工操作。**

代码层面：后端 82 项自动化断言全通过，前端静态检查零问题，包体积 141.2 KB，落地页首屏 1 次请求，全部功能链路完整可用。

风险点集中在微信审核：落地页展示二维码属于审核敏感形态，已通过「做成商家卡片而非纯二维码页」「提审用合规素材」等方式降低风险，但**无法保证一次过审**，需以微信官方最新审核规范为准，驳回后按意见整改。
