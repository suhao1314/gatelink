## 一、基本信息

| 项 | 内容 |
|---|---|
| 项目名 | GateLink 活码台 |
| 定位 | 面向校园团长、本地商家、渠道代理的活码工具：一个码挂多张二维码，按策略轮换展示，统计每条渠道的访问效果 |
| 当前版本 | v1.2（首版完成三轮开发与验收） |
| 代码规模 | 小程序 6 个页面，后端 22 个源文件，21 个 REST 接口 + 2 个 H5 页面路由 |
| 许可证 | MIT |

## 二、技术栈

| 层 | 选型 |
|---|---|
| 小程序 | 微信原生，WebView 渲染，无第三方 UI 库 |
| 后端 | Node.js 22 + 内置 `http` 模块（零 Web 框架依赖） |
| 数据库 | SQLite（Node 内置 `node:sqlite`，需 `--experimental-sqlite`） |
| 二维码 | 服务端 `qrcode` 包生成 PNG/SVG，带文件缓存 |
| 存储 | 服务器本地目录 + nginx 静态分发 |
| 部署 | 轻量服务器 + nginx 反代 + PM2 |

## 六、上线前必须人工完成

代码写完了不等于能上线，以下每一步都需要在微信公众平台和服务器上手动操作：

1. 注册小程序并取得 AppID / AppSecret
2. 配置 request 合法域名（HTTPS + 已备案）
3. 配置「扫普通链接二维码打开小程序」前缀规则 + 上传域名校验文件
4. 完成小程序备案
5. 填写用户隐私保护指引
6. 确认服务类目（以官方最新类目表为准）
7. 提审用落地页使用自有合规素材
8. 服务器安装 Node 22.5+、配置 PM2、nginx 反代与 HTTPS 证书

详细验收口径见 `04-acceptance.md`。

## 七、合规边界（不可越过）

这个项目能做什么、不能做什么，写死在这里：

| 可以做 | 不可做 |
|---|---|
| 统计落地页访问量、独立访客、时段、地域 | 声称能识别用户是否成功添加好友 |
| 按策略轮换展示商家上传的二维码 | 代用户操作微信、Hook、机器人、逆向接口 |
| 给商家提供物料导出 | 收集访客的微信昵称、头像、通讯录、聊天记录 |
| 提醒群码即将过期或满员 | 承诺「绕过微信限制」「防封防红」 |

对外文案的红线：写「统计扫码访问」，不写「自动识别来源」；写「展示商家提供的二维码」，不写「保证成功添加」。
